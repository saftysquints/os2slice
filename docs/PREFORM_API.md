# PreForm Server API (Formlabs Form 4)

What the `preform-server` module (`src/os2slice/modules/preform.py`) relies on. ✅ = called live against `formlabs/preform-server:release-3.64.1.664` on 2026-10-15/16: the whole prepare path (create → save, reopen), errors, async, restarts and discovery, plus one real upload to a Form 4's queue (`print_now: false`). **Nothing here has been verified from os2slice yet.** Unmarked rows are read from Formlabs' developer docs (`https://developer.formlabs.com`) or the OpenAPI spec (`https://developer.formlabs.com/reference/openapi-v1.yml`, PreForm API **1.0.0-alpha**); where the server and the spec disagree, the row says so. Verify before relying on an unmarked row, and update this file.

PreForm Server is PreForm without its window, behind a local HTTP API, shipped by Formlabs as an official Linux container. It replaces os2slice's D-2 ("No PreForm on Linux") and issue #2's plan (a community Wine image and the old 0.9 API, whose paths no longer exist in v1). Reverse engineering PreForm isn't needed.

## The server

|---|---|
| Image | `formlabs/preform-server` on Docker Hub ("PreForm Server for Linux" in developer.formlabs.com's Downloads). Tags: `release-latest` (moves) and `release-<version>` (one build; the version `GET /v1/` reports), e.g. `release-3.64.1.664`. ✅ |

Runs under Docker's default seccomp and AppArmor's `docker-default` with no denials. ✅ |
| Size, memory | 334 MB compressed, 1.27 GB unpacked. ~150 MB idle; ~0.5 GB after one part's prepare path; ~1.4 GB with 20 supported parts. It keeps what it grew to until restarted. ✅ |
| Speed | One small part: every call under 0.7 s (thin-features 1.6 s). On an i7-10710U NUC: auto-support 1.4 s, 20 copies' auto-layout 18.5 s, print time 6.2 s. ✅ |
| Start | `READY FOR INPUT` ~1 s after start. `--port` is required. ✅ |
| CLI | `-p/--port`, `--scene-cache-size` (default 30, LRU), `--export-support-bundle`, `-v`, `-h`. **No bind option**: it listens on every interface in the container, so never run it with `--network host`. ✅ (port, cache), docs (the rest) |
| Restart | **With the image's own `/tmp`, a restarted container never comes back** (Xvfb finds its old `/tmp/.X99-lock` and the entrypoint waits forever while the container shows "Up"). **A tmpfs `/tmp` fixes it.** A restarted server has no scenes (one new empty `UNKN-0-0` scene), no operations and no printers until they're discovered again. ✅ |
| Concurrency | Other requests are served while a long call runs. ✅ |
| Auth | **None.** Anything that reaches the port drives the server, printing included. **CORS is open** (any `Origin` echoed with credentials, JSON accepted as `text/plain`), so a browser that can reach the port is a way in. Never publish the port on the LAN. ✅ |
| User | Runs as root by default; `--user "<uid>:<gid>"` works and its files are then that user's. ✅ |
| Files | Paths in requests are **inside the server's container**. Mount a shared folder and use paths under it (os2slice's `share_dir`, seen by the server as `server_share_dir`). Imports work from a read-only mount; saving to one fails. It keeps per-layer files in `/tmp/PreFormServer-*/` (~25 MB). ✅ |
| Telemetry | On by default; `-e DISABLE_PREFORMSERVER_TELEMETRY=1` turns it off. ✅ |

```bash
docker run -d --restart unless-stopped --name preform-server \
  -e DISABLE_PREFORMSERVER_TELEMETRY=1 --tmpfs /tmp:size=1g,mode=1777 \
  -v /share/os2slice/preform:/share/os2slice/preform \
  formlabs/preform-server:release-3.64.1.664 --port 44388
```

No `-p`: os2slice reaches it on the containers' own network (Docker Compose: `http://preform-server:44388`; Home Assistant add-on: `http://local-preform-server:44388`). Mounting the shared folder at the same path in both containers leaves `server_share_dir` empty. The printer is reached from Docker's bridge by IP (below); no host networking is needed. ✅ (a Docker deployment on an Ubuntu 24.04 NUC)

## Requests

JSON bodies on `POST` and `DELETE` (and `GET /v1/device/list/` takes an optional one). Failures are `{"error": {"code", "message"}}`; match on `code`, never `message` (spec). A call with no result (render, save, scene and model delete) answers 200 with an **empty body and no Content-Type**. ✅

- **Unknown scene id**: every scene call (get, delete, save, render, both print-time calls, metadata, model list/import/orient/translate/duplicate/auto-orient/auto-support/auto-layout/fill-build-platform/delete, every check) answers **400 `INPUT_ERROR` "Scene with given scene_id not found"**, with or without `?async=true`. A deleted, evicted or pre-restart scene answers the same, so they can't be told apart: reopen the job's `.form`. A malformed id → 400 `INPUT_ERROR` "Invalid scene_id format" (save: "Invalid scene_id format in scene_ids"). ✅
- **Async**: long calls take `?async=true` → **202** `{operation_id, operation_url, message}` and a `Location` header equal to `operation_url` (`/v1/operation/get/?operation_id=<id>`). The request is checked first: a bad scene id or schema error is a plain 400 and no operation. Poll `GET <operation_url>`: `{id, progress, status: "IN_PROGRESS"}`, then either `{id, progress: 1, status: "SUCCEEDED", result}`, where `result` is the call's 200 body (**absent** for calls with no body, e.g. save), or `{id, progress: 1, status: "FAILED", result: {error: {code, message}}}`, the same envelope a blocking call returns. FAILED seen for: import of a missing file, save to an unwritable path, auto-layout with an unknown model. ✅
- **`progress` is coarse**: the first poll already says 0.5 or 0.67; import, auto-layout, print time and save stay there and then jump to 1; auto-support crept 0.51 → 0.72 over 9 s, then 1. Show "working", not a percentage. ✅
- `&mode=oneshot` on `operation/get` deletes a finished record as it's read (read again → 404 `NOT_FOUND` "Operation with given ID not found"); the default `persistent` keeps it until `DELETE /v1/operation/delete/` `{operations: [id]}` (200, empty) or a restart. `POST /v1/operation/list/` (`{}` or no body; `{operations: [ids]}` filters) → `{count, operations: [{id, progress, status}]}`, no results. No `operation_id` → 400 `MISSING_QUERY_PARAMETER`; `?async=maybe` → 400 `INVALID_QUERY_PARAMETER`. The API can't cancel an operation (docs). ✅
- Without `async`, every call blocks and returns its result.

## Form 4 catalog (3.64.1.664) ✅

From `print-setting/list`. **Form 4** and **Form 4B** are both `machine_type: "FORM-4-0"` (200 × 125 × 210 mm); Form 4L / 4BL are `FRML-4-0` (353 × 196 × 350 mm). Form 4 layer thicknesses: 0.025, 0.05, 0.1, 0.16, 0.2 mm, varying by material. Some materials list several `print_setting`s for one layer (Grey V5 at 0.1: `DEFAULT` and `FINERTOUCHPOINTS`; Tough 2000 V2: `SUPPORTSV1` "(Default settings)" and `SUPPORTSV2`, no `DEFAULT`). 27 Form 4 materials, among them Black V5 `FLGPBK05`, Clear V5 `FLGPCL05`, Grey V5 `FLGPGR05`, White V5 `FLGPWH05`, Rigid 4000 V1 `FLRGWH01`, Tough 2000 V2 `FLTO2002`, Tough 1500 V2 `FLTO1502`, Durable V2.1 `FLDUCL21`, High Temp V2 `FLHTAM02`, Flexible 80A V2 `FLFL8002`. A new PreForm release can add or change them; the module reads the catalog and hard-codes none.

## How the module uses it

- **Profiles.** An SLA printer reuses the FDM profile slots: `printer` = machine type (`FORM-4-0`), `process` = layer height (`"0.1 mm"`), `filament` = material code (`FLGPGR05`). Materials are offered by code, the tank's first ("Rigid 4000 V1 (loaded)"), then every catalog material for the machine type. A scene is made with the catalog's own `scene_settings` for (machine type, material, layer): `print_setting` `DEFAULT`, else the one labelled "(Default settings)", else the first.
- **Printers.** `GET /v1/device/list/` without `VIRTUAL` devices; each configured address it lacks is looked up with `device/discover` `{timeout_seconds: 3, printer: <address>}` (blocking), and not again for 60 s after a failure. The catalog is kept 10 minutes. Product name → the catalog's printer type with that `label` → machine type and build volume.
- **Slice.** One job folder under `share_dir`; all parts merged into one binary STL; `scene/create` → `model/import` (`MILLIMETERS`, `REPAIR`) → `model/auto-orient` or `model/orient` `{linear: identity}` (keeps os2slice's orientation, seats the part on the platform) → `model/auto-support` unless supports are off (with `raft_type` when configured) → `model/duplicate` `count: copies-1` → `model/auto-layout` (its `OPERATION_FAILED` = the copies don't fit) → checks (`in-bounds`, `manifoldness`; with supports `cups`, `minima`, `supportedness`) as warnings → `calculate-print-time` → `scene/get` → `scene/save` → read the `.form`. The scene and folder are deleted afterwards, also on failure.
- **Submit.** Write the `.form` to a new job folder, `scene/open`, make sure the printer is listed (discover by its IP, else its id), `scene/print` `{scene_id, printer: <IP, else device id>, job_name, print_now}`, then delete the opened scene and the folder.
- Async calls use `?async=true` and poll `GET /v1/operation/get/?operation_id=<id>&mode=oneshot` every second (up to 30 minutes, a "still working" line every 30 s). Errors become `ModuleError("PreForm Server: <message>")`, with the fix chosen by `code`.

## Rules for os2slice

- **`print_now` is always sent**, never left out (omitted, a ready printer starts at once). It is `true` only when the person asked to start and `[targets.<key>] remote_start` is on (D-36); otherwise every job waits in the printer's queue until someone starts it on the touchscreen. The module refuses to call `scene/print` without an explicit boolean. Tests and scripts never upload to a real printer without an explicit flag and Josh at the printer.
- Never publish the server's port on the LAN, and never run it with `--network host`: it has no auth and open CORS.
- Run it with a tmpfs `/tmp`, or a restart leaves it dead.
- Pin a full image tag and set `version` to it; `doctor` warns when `GET /v1/` reports another. The API is `1.0.0-alpha`.
- One scene per job, deleted afterwards; take scene and model ids from each response, never "the first scene". The module never touches a scene it didn't create, never logs in and never uploads firmware.
- Find printers by IP (mDNS doesn't reach the container), filter `connection_type: "VIRTUAL"` out, and expect discover's first answer to be partial.
